# TikTok短剧中心 自动注册 + 企业认证 + 设置密码 / 营业执照英译（GUI版）

购买的 Outlook 邮箱（`邮箱----密码----client_id----令牌`）自动注册 TikTok 短剧创作者平台，验证码通过取件API自动获取，登录凭证自动保存；注册后可用美国公司资料自动完成**企业认证**提交（**一个企业最多认证 5 个账号**，机构名一名一用，可复用于后续同格式资料），并自动**设置账户密码**（密码=号池中该账号的邮箱密码，可在界面一键导出 邮箱/密码/企业名 Excel 清单）。另含 **A 格式公司法人营业执照** 照片 → 固定英文模板 PDF。

## 小白使用

**双击 `启动.bat` 即可。** 顶部两个页签：

| 页签 | 做什么 |
|---|---|
| **短剧注册** | 导入账号/机构名、号池、自动注册 + 企业认证 + 设置密码 |
| **执照翻译** | 加入中文营业执照照片，批量转成英文模板 PDF（第 1 页译文，第 2 页原件）。只处理 A 格式公司法人执照；个体户/合伙/分公司会标「非A格式」。红章日期看不清可勾选「指定发证日期」 |

首次运行会自动安装依赖（playwright + openpyxl + Chromium浏览器，约150MB），之后秒开。执照翻译页第一次点「开始转换」会再装 OCR 相关库。

界面四步走：
1. **① 导入账号**：点「选择 txt 文件导入…」选账号文件，或把账号文本粘贴到框里点「导入下方粘贴内容」
2. **② 导入机构名**：认证表单里的「机构名称」不再填公司名，改从机构名库**按队列唯一分配（一名一用，一个机构名只能用于一次认证）**；同样支持 txt 文件 / 粘贴导入，每行一条（可带序号），重复自动跳过，库存在 `institutions.json`。**长度上限 30 字符**（表单输入框 `maxLength:30` 前端实证，超长会被浏览器截断导致认证必然失败）——超长的导入时直接拒收、分配时自动跳过；历史库可用 `python clean_institutions.py` 一键改名清洗（自动备份原库）
3. **③ 号池**：自动显示所有账号与状态（可用/已注册/失败 + 企业认证状态 + 机构名 + 密码状态 + 出口IP），失败的可以一键重置；「导出Excel…」一键导出已注册账号的 邮箱/密码/密码状态/企业认证公司/机构名/认证状态/注册时间；「归档资料不全」把资料不全且未绑定的公司移入 `资料/资料不全/`（xlsx汇总表删除对应行并自动备份原表到归档目录，同时清理 overrides.json 条目；已绑定账号的公司保留绑定历史不归档）；**「▶ 登录选中账号」**：选中一个已注册账号后点击，自动完成登录并**保持浏览器打开**供人工查看（如查看认证审核状态）——优先用 `auth/` 里保存的登录会话，过期自动邮箱验证码重登（不消耗新账号）；再次登录其他账号或退出界面时自动关闭上一个登录窗口
4. **④ 自动注册 + 企业认证 + 设置密码**：
   - 勾选「注册后自动企业认证」→ 每个账号注册成功后立即绑定公司槽位提交认证（**每企业最多认证 5 个账号**，先填满一家再换下一家；「每企业认证账号数」固定 5 不可改），随后自动设置账户密码
   - 或点「▶ 认证已注册账号」单独给已注册账号批量做认证（登录会话过期会自动用验证码重登）
   - 或点「▶ 设置密码」单独给已注册账号批量设置账户密码（密码=号池中该账号的邮箱密码；已设置的自动跳过）

> 提示：默认会弹出浏览器窗口展示操作过程（过风控更稳）；勾选「无头模式」则后台静默跑。
> 运行日志留档在 `gui.log`，每步截图在 `logs/`，出问题时打包这两个反馈即可。

## HubStudio 指纹浏览器模式（2026-09-08 新增）

④区「HubStudio指纹浏览器」勾选框（**默认勾选**）开启后，自动化不再裸起 Chromium，改为接管 HubStudio 客户端的指纹环境：指纹（UA/时区/Canvas·WebGL·Audio 噪音/WebRTC 隐藏）与 SOCKS5 代理全部由环境承载，引擎侧不传 UA/时区/视口、不注入 webdriver 覆写（ChroBrowser 自带反检测）。

| 项 | 说明 |
|---|---|
| 前置条件 | HubStudio 客户端在运行 + **VIP 及以上套餐**（免费版 API 返回 code 26）；默认环境 `1819191426`（共享团队 PH 出口，已实测站点正常） |
| 工作方式 | Local API `127.0.0.1:6873` 打开环境 → Playwright `connect_over_cdp` 接管 → **单窗交接**：第 1 个账号直接用环境自带 about 窗口（先清默认 profile 残留 cookie、再注入登录凭证），后续每账号新建隔离 context 并关闭上一窗——**任意时刻只有一个浏览器窗口**，每账号仍独立 cookie + 独立出口 IP。必须先建新窗再关旧窗（零窗口浏览器立即退出，2026-09-09 实测） |
| 额度（省着用） | 每次**环境打开**计一次额度；一次打开内串行跑完整批（注册+认证+密码），结束统一关闭——**整批只计 1 次**。启动前预检只查状态不耗额度；崩溃恢复优先复用仍在运行的环境（`hubstudio_state.json` 记录端口，不重开） |
| **每账号新IP**（默认勾选） | **零额度**：代理对每个新 context 自动分配独立出口 PH 住宅 IP（2026-09-09 实测：同一次环境打开内连续 4 个 context 实测 4 个不同 IP），引擎每账号新建 context 即天然换 IP，无需重开环境；同一账号的注册→认证→密码在同一 context 内 IP 不变。勾选后额外实测每账号真实出口 IP，记录到号池 `last_ip` 字段与运行日志（约多一次页面访问，不消耗额度） |
| 失败提示 | 客户端未运行 / 免费版无权限 / 环境不在当前团队 / **API卡死**（端口在监听但超时——客户端残留进程卡住，须重启客户端）→ 预检在工作线程内快速失败（单请求8s超时）并弹窗提示，GUI 不冻结、日志可见原因；可取消勾选改用普通浏览器 |

CLI 等价开关：`python register.py --hubstudio`（注册/认证/密码三个子命令均支持）。

## 企业资料要求（资料/ 文件夹）

同格式的后续资料直接放进文件夹即可复用，无需改代码：

| 文件 | 说明 |
|---|---|
| `资料/*.xlsx` | 汇总表，每行一家公司，固定 12 列布局（列序不变）：A公司名 B注册编号 C注册州 D注册城市 E注册地址 F代表人姓名 G出生日期 H证件号 I证件有效期 J居住州 K居住城市 L居住地址。**必填仅 A + F~I 五列**（证件照片识别不准，代表人 4 项必须表格录入）；B~E（企业注册字段，以 PDF 识别回填为准）和 J~L（表单无对应字段，本就未用）允许留空。不要加序号列 |
| `资料/{公司名}/` | 公司文件：州注册文件（AOG/注册回执/Correspondence）、CP575、证件照 front/back(或1./2.命名) |
| `资料/overrides.json` | 可选：自动识别不了文件角色时人工指定 `{"公司名": {"id_front": "文件名"}}` |
| `资料/usage.json` | 自动维护：槽位制 `{公司: [{email,status,at,note}...]}`，每家公司最多 5 个槽位（账号）（勿手改，失败未提交会自动释放复用对应槽位） |
| `资料/blocked.json` | 自动维护：**服务端拉黑名单**。上传营业执照被服务端以「上限」类原因拒绝时（本地槽位只统计本工具用量，服务端上限含历史/外部认证，可能低估）自动拉黑该公司，后续账号自动换下一家不再白试；删除对应条目可恢复 |

资料校验：缺数据/缺文件/证件过期的公司在界面上计入「资料不全」，不会被使用；点「归档资料不全」可把这类公司整体移入 `资料/资料不全/`（原汇总表备份、xlsx删行、overrides清理，xlsx被Excel占用时整体中止不动文件）。

## 认证表单自动填写映射（实测 2026-09-06；2026-09-08 改为两段式）

**填写顺序（两段式，业务规则：PDF 识别准、证件照片识别不准、冲突以人工录入为准）**：① 先上传除证件正反面外的三组文件（企业营业证明 PDF → 地址证明=证件正面 → CP575），每组传完等 OCR 识别排空——企业注册字段由 PDF 识别**静默回填**（字段为空不弹冲突窗）；② 人工补填：机构名称、国家/地区下拉、营业执照长期有效勾选、证件包含内容单选，**代表人 4 字段用表格值强制覆盖**（照片 OCR 回填的杂值不信任），企业字段仅在识别没填时才用表格值兜底（表格 B~E 列留空则纯依赖识别，识别也没填则报错）；③ 最后上传证件正反面，等 OCR 排空——识别与已填内容不一致弹冲突窗时一律**「保留当前填写」**。

| 表单字段 | 来源 |
|---|---|
| 机构名称 | 机构名库队列分配（`institutions.json`，一名一用，OCR 不回填，必填；不再使用公司名） |
| 企业名称(当地语言/英语) / 注册编号 / 省/州 / 城市 / 注册地址 | **PDF 识别回填为准**；识别没填才用表格值兜底（B/C/D/E 列，可留空） |
| 国家/地区 | OCR 已填则跳过，否则选「美国」 |
| 营业执照有效期 | 识别已填有效期则保留；否则勾选「长期有效」（州注册文件无到期日） |
| 企业营业证明 | 州注册文件（AOG/Correspondence/Business Entity Filing 三种命名均可识别） |
| 身份证件（正反面，多文件） | front + back 证件照（**最后上传**，此后冲突一律保留当前填写） |
| 姓名/出生日期/证件号/证件有效期 | **表格录入为准**（照片识别不准，强制覆盖识别回填值）；表格值来自 F/G/H/I 列 |
| 证件包含内容 | 「地址」（美国驾照含地址） |
| 地址证明 | 证件正面（美国驾照含居住地址，与证件上传同图；第一批上传，此时代表人字段尚空，杂值会在②被表格值覆盖） |
| 代表人证明 | CP575（含公司名+代表人+地址） |

**证件/执照 OCR 识别冲突**：站点上传文件后会异步识别，识别结果与**已填内容**不一致时弹「是否使用证件识别结果覆盖」弹窗（弹窗遮罩会拦截一切点击，且弹出时机不可预测——曾实测在填日期时弹出，与日期面板叠成双层遮罩导致卡死）。处理策略分两段：

1. **上传阶段**（字段尚空，识别是静默回填不弹窗；万一弹出）：企业 PDF 字段点「应用识别结果」
2. **人工补填之后**（代表人字段已按表格录入、证件正反面上传中/提交前后）：一律点「保留当前填写」——证件照片识别不准，以人工录入值为准
3. **自愈点击**：所有点击采用短超时快速失败→清障→重试，弹窗恰好撞上点击瞬间也不会挂死
4. **全程兜底**：每个填表步骤、提交前、提交后等待跳转期间都持续检测处理冲突弹窗

冲突明细（字段、双方值、处理决策）全部写入运行日志留档。

**已提交过认证的账号识别**（2026-09-10 实测）：此类账号点侧栏「企业认证」进入的是**认证管理页**（机构名标题 +「解散机构」按钮 + 筛选 tabs +「认证新企业」按钮 +「企业资质正在审核中」提示），而非新账号的引导页（「立即添加」按钮）。引擎检测到管理页特征即判定「之前已提交过认证」：号池 `cert_status` 直接记 `submitted`（不重跑、不占新槽位、批量计为跳过），并读取页面 header 的**当前生效机构名**——与号池记录不同时以页面为准更新（服务端真相，如机构名库改名前提交的旧名/人工提交）；新分配但平台已有认证的账号会释放本次占用的公司槽位与机构名再对齐历史绑定。

**提交后两种服务端拒绝 toast 的自动处理**（2026-09-10 实测，toast 只显示约 2-3 秒，引擎在提交后 0.5s 高频轮询捕获）：

| toast 文案 | 自动处理 |
|---|---|
| 「机构名称已存在，请重新命名」 | 该机构名在平台侧已被占用：**废弃旧名**（`institutions.json` 标记 `discarded` 终态，永不可复用）→ 自动分配下一个机构名 → **只清填机构名称框重新提交**（其他已填字段与已上传文件全部保留）；连续撞名最多换 5 次，库中无可用名时报错 |
| 「识别到当前企业已重复认证，不可再发起」 | 该营业执照在服务端侧已无认证额度：**拉黑该公司**（等同满槽位，后续账号不再白试）→ 释放本邮箱槽位 → **goto 到不带申请单 ID 的 `create/` 打开全新表单**（带 ID 刷新会恢复旧申请单草稿，实测 URL 形如 `create/7683889452686890002`）→ 自动顺延下一组企业重新填写提交（机构名未被服务端使用，续用；最多换 6 家） |
| 提交报错（toast 含「错误」两字或「500」） | 服务端瞬时错误：**重新点击提交按钮**即可（表单数据仍在），最多重试 10 次，仍失败才报错 |
| 上传时英文 60s 超时 toast（含 timeout / time out / 60s，文案短词匹配） | 网络/前端超时，文件没传上去：**goto 到不带申请单 ID 的 `create/` 打开全新表单，同一组公司+机构名整组重新上传填写**（绑定未失效，区别于换公司场景）；最多重跑 3 次 |

## 设置密码流程（2026-09-07 新增，password_setter.py）

注册/认证后在同一登录态下自动完成：右上角账户头像 → Floating UI 账户菜单 → 「设置密码」→ 密码弹窗 → 两次输入 → 确认提交 → 结果判定。

| 项 | 说明 |
|---|---|
| 密码来源 | 号池中该账号的邮箱密码字段（不硬编码、不生成；导出Excel即完整账号密码清单） |
| 定位策略 | 语义属性优先（`aria-haspopup` / `data-floating-ui-portal` / `data-testid=minidrama-dialog` / `#password` / `#confirmPassword`），不依赖 React 动态ID 与构建 hash class；菜单与弹窗用「退出登录」文本 / 密码输入框特征互相区分 |
| 成功判定 | 弹窗关闭 + 无错误 toast / 校验文本；点击后监听本次提交的响应（历史 Console 404 不参与判定） |
| 安全约定 | 「确认」只点击一次（有副作用，超时先复核响应记录绝不盲重试）；密码明文永不写日志（只记长度）；截图为掩码输入框；提交后若要求验证码/邮件验证则标记 `REQUIRES_VERIFICATION` 交人工接管，不绕过 |
| 状态记账 | 号池 `pwd_status`（success/already/failed/unconfirmed）+ `pwd_at` + `pwd_error`；已设置过密码的账号菜单项变「重置密码」（2026-09-09 实测 DOM），自动识别跳过并记账为「之前已设置」，导出 Excel 同文案 |
| 跳转链路 | `certifier.ensure_home()` 统一管理进入已登录/home：已在登录态直接复用当前页面（不重复goto整页重载），需要跳转时用「侧栏标记+头像出现」精确等待替代全文稳定采样；会话失效提前判定触发重登（含2秒宽限复核，防落地页→登录态切换竞态误判） |
| 失败细分 | AVATAR_NOT_FOUND / ACCOUNT_MENU_NOT_OPENED / SET_PASSWORD_ITEM_NOT_FOUND / PASSWORD_DIALOG_NOT_OPENED / PASSWORD_INPUT_NOT_FOUND / CONFIRM_PASSWORD_INPUT_NOT_FOUND / PASSWORD_VALIDATION_FAILED / SUBMIT_BUTTON_NOT_FOUND / SUBMIT_TIMEOUT / SERVER_REJECTED / ALREADY_SET / REQUIRES_VERIFICATION / SESSION_INVALID / NAV_FAILED |

## 命令行（可选）

```powershell
python run_gui.py --auto 5     # 启动GUI并自动开始注册5个(跳过确认, 完成自动退出)
python run_gui.py --auto -1    # max模式(全部可用账号)
python register.py --count 5   # 纯CLI: 注册5个并自动认证+设置密码
python register.py --no-cert   # 只注册(不做认证/密码等附加任务)
python register.py --cert      # 只认证: 批量处理已注册未认证账号
python register.py --pwd       # 只设置密码: 批量给已注册账号设置账户密码
python register.py --hubstudio # 以上命令均可加: 接管HubStudio指纹环境(VIP套餐)
python register.py --hubstudio --rotate-ip  # 再加: 实测并记录每账号出口IP(零额度, 代理自动隔离)
python batch.py 照片.jpg -o license_out     # 执照翻译CLI: 照片→英文模板PDF
python batch.py 照片文件夹 -o license_out --issue-date 2022-12-09
```
