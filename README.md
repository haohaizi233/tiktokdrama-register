# TikTok短剧中心 自动注册 + 企业认证 + 设置密码工具（GUI版）

购买的 Outlook 邮箱（`邮箱----密码----client_id----令牌`）自动注册 TikTok 短剧创作者平台，验证码通过取件API自动获取，登录凭证自动保存；注册后可用美国公司资料自动完成**企业认证**提交（一司一号，可复用于后续同格式资料），并自动**设置账户密码**（密码=号池中该账号的邮箱密码，可在界面一键导出 邮箱/密码/企业名 Excel 清单）。

## 小白使用

**双击 `启动.bat` 即可。**

首次运行会自动安装依赖（playwright + openpyxl + Chromium浏览器，约150MB），之后秒开。

界面三步走：
1. **① 导入账号**：点「选择 txt 文件导入…」选账号文件，或把账号文本粘贴到框里点「导入下方粘贴内容」
2. **② 号池**：自动显示所有账号与状态（可用/已注册/失败 + 企业认证状态 + 密码状态），失败的可以一键重置；右侧显示公司资料可用数；「导出Excel…」一键导出已注册账号的 邮箱/密码/密码状态/企业认证公司/认证状态/注册时间；「归档资料不全」把资料不全且未绑定的公司移入 `资料/资料不全/`（xlsx汇总表删除对应行并自动备份原表到归档目录，同时清理 overrides.json 条目；已绑定账号的公司保留绑定历史不归档）
3. **③ 自动注册 + 企业认证 + 设置密码**：
   - 勾选「注册后自动企业认证」→ 每个账号注册成功后立即绑定一家公司提交认证，随后自动设置账户密码
   - 或点「▶ 认证已注册账号」单独给已注册账号批量做认证（登录会话过期会自动用验证码重登）
   - 或点「▶ 设置密码」单独给已注册账号批量设置账户密码（密码=号池中该账号的邮箱密码；已设置的自动跳过）

> 提示：默认会弹出浏览器窗口展示操作过程（过风控更稳）；勾选「无头模式」则后台静默跑。
> 运行日志留档在 `gui.log`，每步截图在 `logs/`，出问题时打包这两个反馈即可。

## 企业资料要求（资料/ 文件夹）

同格式的后续资料直接放进文件夹即可复用，无需改代码：

| 文件 | 说明 |
|---|---|
| `资料/*.xlsx` | 汇总表，每行一家公司，列序固定：A公司名 B注册编号 C注册州 D注册城市 E注册地址 E代表人姓名 G出生日期 H证件号 I证件有效期 J居住州 K居住城市 L居住地址 |
| `资料/{公司名}/` | 公司文件：州注册文件（AOG/注册回执/Correspondence）、CP575、证件照 front/back(或1./2.命名) |
| `资料/overrides.json` | 可选：自动识别不了文件角色时人工指定 `{"公司名": {"id_front": "文件名"}}` |
| `资料/usage.json` | 自动维护：每家公司绑定到哪个邮箱、认证结果（勿手改，失败未提交会自动释放复用） |

资料校验：缺数据/缺文件/证件过期的公司在界面上计入「资料不全」，不会被使用；点「归档资料不全」可把这类公司整体移入 `资料/资料不全/`（原汇总表备份、xlsx删行、overrides清理，xlsx被Excel占用时整体中止不动文件）。

## 认证表单自动填写映射（实测 2026-09-06；2026-09-07 改为上传先行）

**填写顺序（上传先行）**：① 四组文件先上传（企业营业证明 → 证件正反面 → 地址证明=证件正面 → CP575），每组传完等 OCR 识别排空——**字段为空时识别是静默回填，不弹冲突窗**，从根源消除"预填文本→识别→冲突"竞态；② 识别不覆盖的控件手动填：机构名称、国家/地区下拉、营业执照长期有效勾选、证件包含内容单选（识别已回填的同样跳过）；③ 其余文本/日期字段**补录**：识别已填的保留识别值（审核以证件图片为准），仍为空的才填资料值。

| 表单字段 | 来源 |
|---|---|
| 机构名称 | 公司名（OCR 不回填，必填） |
| 企业名称(当地语言/英语) / 注册编号 / 省/州 / 城市 / 注册地址 | OCR 回填优先；空则补录汇总表 B/C/D/E 列 |
| 国家/地区 | OCR 已填则跳过，否则选「美国」 |
| 营业执照有效期 | 识别已填有效期则保留；否则勾选「长期有效」（州注册文件无到期日） |
| 企业营业证明 | 州注册文件（AOG/Correspondence/Business Entity Filing 三种命名均可识别） |
| 身份证件（正反面，多文件） | front + back 证件照 |
| 姓名/出生日期/证件号/证件有效期 | OCR 回填优先；空则补录汇总表 F/G/H/I 列 |
| 证件包含内容 | 「地址」（美国驾照含地址） |
| 地址证明 | 证件正面（美国驾照含居住地址，与证件上传同图） |
| 代表人证明 | CP575（含公司名+代表人+地址） |

**证件/执照 OCR 识别冲突**：站点上传文件后会异步识别，识别结果与**已填内容**不一致时弹「是否使用证件识别结果覆盖」弹窗（弹窗遮罩会拦截一切点击，且弹出时机不可预测——曾实测在填日期时弹出，与日期面板叠成双层遮罩导致卡死）。上传先行让识别发生在字段为空时，正常情况下不再产生冲突弹窗；以下防御保留作为兜底：

1. **主动排空**：每个文件上传后主动等该文件识别完成（期间弹出的冲突弹窗立即处理），把冲突收敛到安全时点
2. **自愈点击**：所有点击采用短超时快速失败→清障→重试，弹窗恰好撞上点击瞬间也不会挂死
3. **全程兜底**：每个填表步骤、提交前、提交后等待跳转期间都持续检测处理冲突弹窗

处理策略统一为**应用识别结果**（以证件图片为准，审核看的就是图片；站点日期控件还有 -1 天的显示偏移 bug，识别结果恰好能纠偏）。若识别结果覆盖了正在填写的字段，以识别结果为准不视为失败，冲突明细全部写入运行日志留档。

## 设置密码流程（2026-09-07 新增，password_setter.py）

注册/认证后在同一登录态下自动完成：右上角账户头像 → Floating UI 账户菜单 → 「设置密码」→ 密码弹窗 → 两次输入 → 确认提交 → 结果判定。

| 项 | 说明 |
|---|---|
| 密码来源 | 号池中该账号的邮箱密码字段（不硬编码、不生成；导出Excel即完整账号密码清单） |
| 定位策略 | 语义属性优先（`aria-haspopup` / `data-floating-ui-portal` / `data-testid=minidrama-dialog` / `#password` / `#confirmPassword`），不依赖 React 动态ID 与构建 hash class；菜单与弹窗用「退出登录」文本 / 密码输入框特征互相区分 |
| 成功判定 | 弹窗关闭 + 无错误 toast / 校验文本；点击后监听本次提交的响应（历史 Console 404 不参与判定） |
| 安全约定 | 「确认」只点击一次（有副作用，超时先复核响应记录绝不盲重试）；密码明文永不写日志（只记长度）；截图为掩码输入框；提交后若要求验证码/邮件验证则标记 `REQUIRES_VERIFICATION` 交人工接管，不绕过 |
| 状态记账 | 号池 `pwd_status`（success/already/failed/unconfirmed）+ `pwd_at` + `pwd_error`；已设置过的账号菜单项变「修改密码」，自动识别跳过 |
| 跳转链路 | `certifier.ensure_home()` 统一管理进入已登录/home：已在登录态直接复用当前页面（不重复goto整页重载），需要跳转时用「侧栏标记+头像出现」精确等待替代全文稳定采样；会话失效提前判定触发重登（含2秒宽限复核，防落地页→登录态切换竞态误判） |
| 失败细分 | AVATAR_NOT_FOUND / ACCOUNT_MENU_NOT_OPENED / SET_PASSWORD_ITEM_NOT_FOUND / PASSWORD_DIALOG_NOT_OPENED / PASSWORD_INPUT_NOT_FOUND / CONFIRM_PASSWORD_INPUT_NOT_FOUND / PASSWORD_VALIDATION_FAILED / SUBMIT_BUTTON_NOT_FOUND / SUBMIT_TIMEOUT / SERVER_REJECTED / ALREADY_SET / REQUIRES_VERIFICATION / SESSION_INVALID / NAV_FAILED |

## 数据存放

| 位置 | 说明 |
|---|---|
| `pool_data/` | 号池：每次导入生成一个json，界面显示的是文件夹内**全部json合并去重**后的总号池 |
| `auth/{邮箱}.json` | 登录凭证（结构化：email/platform/status/时间/cookies），可恢复登录态 |
| `资料/usage.json` | 公司↔账号绑定与认证结果 |
| `gui.log` | GUI运行日志留档 |
| `logs/` | 每步截图与失败现场 |

## 命令行（可选）

```powershell
python run_gui.py --auto 5     # 启动GUI并自动开始注册5个(跳过确认, 完成自动退出)
python run_gui.py --auto -1    # max模式(全部可用账号)
python register.py --count 5   # 纯CLI: 注册5个并自动认证+设置密码
python register.py --no-cert   # 只注册(不做认证/密码等附加任务)
python register.py --cert      # 只认证: 批量处理已注册未认证账号
python register.py --pwd       # 只设置密码: 批量给已注册账号设置账户密码
```

## 架构

```
启动.bat / run_gui.py   入口: tkinter缺失自动切换解释器, 依赖缺失自动安装
└─ gui_app.py           界面: 导入/号池/注册+认证+密码三区, 线程+queue通信, 可停止, 导出Excel
   ├─ pool.py           号池: pool_data/多json合并去重, 状态+认证/密码状态维护
   ├─ registrar.py      注册引擎: login_with_code邮箱验证码登录(GUI/CLI/认证/密码共用), save_auth凭证保存
   │  └─ mail_api.py    取件: POST /api/v1/tool/mail/search 轮询+验证码提取
   ├─ certifier.py      认证引擎: open_session会话恢复/过期重登+表单填写+上传+提交, 一司一号记账
   │  └─ materials.py   资料解析: xlsx+公司文件夹+文件角色识别+用量跟踪
   ├─ password_setter.py 密码引擎: 账户菜单→设置密码弹窗→提交→结果判定, 批量独立运行
   └─ pool_data/ auth/ 资料/ logs/
```
